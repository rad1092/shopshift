# ShopShift 빠른 시작

ShopShift는 기존 ERP를 유지하면서 일정만 검토하는 1인 계획 담당자용 오프라인 앱입니다. ERP나 생산 설비에 데이터를 쓰지 않습니다.

## 처음 실행

릴리스에서 운영체제와 CPU에 맞는 압축 파일을 받아 전체 폴더를 풀고 실행합니다. macOS는 ShopShift.app, Windows는 ShopShift.exe, Linux는 ShopShift 실행 파일입니다. 바이너리는 서명·공증되지 않았습니다. 시스템 보안 기능을 끄지 마세요. 조직 정책으로 실행이 막히면 관리자에게 검토를 요청하거나 소스 설치를 사용하세요. 자세한 요구 사항은 DISTRIBUTION.md를 확인하세요.

소스 설치는 Python 3.12/3.13에서 `python -m pip install .` 이후 `shopshift`입니다. 개발·검증에는 `uv sync --locked --extra dev`를 사용할 수 있습니다. 앱 자체는 네트워크를 사용하지 않습니다.

## 첫 유용한 일정

1. 예제 프로젝트를 열어 화면을 익히거나 새 프로젝트에서 시간대와 계획 기간을 정합니다.
2. ERP에서 작업별 CSV 또는 XLSX를 내보냅니다. 첫 행은 열 이름이어야 합니다. 작업 ID는 매번 동일해야 합니다.
3. 가져오기에서 작업 ID, 주문/작업 묶음, 설비, 실행 시간 등의 열을 연결합니다. 선택적으로 작업자, 준비 시간, 선행 작업 ID, 착수 가능일, 납기를 연결합니다. 시간 단위를 확인합니다.
4. 추가·변경·유지된 작업을 검토한 뒤 적용합니다. 새 설비와 작업자의 기본 캘린더는 평일 08–12시/13–17시이며 실제 근무시간으로 수정해야 합니다.
5. 설비와 작업자 캘린더를 확인합니다. 점심, 휴무, 야간 작업을 절대 시작/종료 시각으로 설정할 수 있습니다. 하나의 작업은 닫힌 시간을 가로질러 자동 분할되지 않습니다.
6. 제안을 요청하면 OR-Tools가 제한된 시간 안에 일정을 찾습니다. 상태와 변경 내역을 검토하고 적용합니다. 빨간 충돌 항목을 선택해 겹침, 선후관계, 캘린더 문제를 확인합니다.
7. 작업을 드래그하거나 편집창에서 시작 시간을 입력합니다. 고정할 작업은 잠급니다. 실수는 실행 취소로 복구합니다.
8. 날짜를 선택해 일일 CSV/HTML 계획을 내보내거나 인쇄합니다. 프로젝트를 저장합니다.

## 다음 날 재가져오기

저장한 프로젝트를 열고 새 ERP 파일을 가져옵니다. 열 매핑과 시간 단위를 재사용할 수 있습니다. 같은 작업 ID의 시작 시간과 잠금은 모든 시나리오에서 유지됩니다. ERP 실행 시간이 늘거나 설비가 바뀌면 기존 결정이 충돌을 만들 수 있으므로 반드시 다시 검토합니다. 파일에서 빠진 작업은 삭제하지 않고 유지합니다. ID를 바꾸면 새 작업으로 인식됩니다.

시나리오를 복사해 대안을 검토하고 비교한 뒤 사용할 안을 선택할 수 있습니다. 제안이나 수입 검토를 취소하면 원래 프로젝트를 유지합니다.

## 시간과 오류

날짜는 `2026-10-05T08:00:00+09:00`처럼 오프셋이 있는 ISO 형식을 권장합니다. 현지 시각만 입력하면 프로젝트 시간대를 사용합니다. 서머타임 전환으로 존재하지 않거나 두 번 등장하는 시각은 명시적 오프셋이 필요합니다. 소수 시간은 정수 초로 정확히 환산할 수 있어야 합니다.

행 오류·중복 ID·수식 셀·손상 파일은 부분 적용하지 않습니다. 오류 메시지의 행/열을 고쳐 다시 수입하세요. XLSX는 첫 번째 워크시트의 표를 사용합니다.

저장 시 이전 파일은 `.bak`으로 남습니다. 손상된 원본을 자동으로 덮어쓰지 않습니다. 복원에서 백업을 명시적으로 열고 내용 확인 후 새 이름으로 저장하세요. 백업은 암호화되지 않습니다.

저장 형식의 크기·개수 제한을 넘는 변경은 적용 전에 거부하며 현재 프로젝트와 실행 취소 기록을 유지합니다. 일정 겹침이나 선후관계 충돌은 검토용 초안으로 저장할 수 있습니다.

## 해석의 한계

최적 상태는 명시된 목적함수에 한정됩니다. 목적함수는 작업별 지연 시간 합과 일정 완료 시간을 같은 가중치로 최소화합니다. 실제 현장 최적이나 납기 보장을 뜻하지 않습니다. 시간 제한에서 찾은 실행 가능 결과는 최적 증명이 없을 수 있습니다. 자재, 재고, 대체 설비, 작업자 기술, 외주, 실시간 고장, 복수 계획 담당자는 모델에 포함되지 않습니다.
